One command sets up a project with layouts, components, content schemas, search, sitemap, OG images, and a markdown alternate for every page.

## Requirements

- **Node** 22.12 or later
- **A package manager** — npm, pnpm, yarn, or bun
- **Git** — for edit links and last-updated dates

## Scaffold

```sh
npx @cloudflare/create-nimbus-docs@latest
```

Pick a directory name, then choose your preferences:

<Steps>
  <Step title="Template">
    Two choices — **full** (core components, demo content, populated theme tokens) or **empty** (the minimum to run, ready for your own content).
  </Step>
  <Step title="Output mode">
    **Static** prerenders every content collection route and deploys anywhere. **Server** uses Cloudflare to render those routes on request. You can override individual collections later.
  </Step>
  <Step title="Target">
    Static output supports Cloudflare or another static host. Interactive server setup currently offers Cloudflare Workers; explicit `--adapter` flags also support Vercel, Netlify, and Node.
  </Step>
  <Step title="Install dependencies">
    The scaffolder runs your package manager automatically. Skip if you want to edit `package.json` first.
  </Step>
</Steps>

## What lands in your repo

<FileTree>
- my-docs/
  - src/
    - components/
      - ui/
    - content/
      - docs/
    - pages/
    - styles/
      - globals.css
    - components.ts
  - astro.config.ts
  - package.json
</FileTree>

The `nimbus-docs` npm package ships the invisible plumbing (integration, data helpers, schemas). Everything visible — components under `src/components/`, MDX content under `src/content/docs/`, routes under `src/pages/`, design tokens in `src/styles/globals.css`, and the MDX globals registry at `src/components.ts` — copies into your repo and is yours to edit.

## Run

<PackageManagers pkg="dev" type="run" />

Then open the printed URL.

## Build and deploy

<PackageManagers pkg="build" type="run" />

Static scaffolds emit `dist/` for any static host. Cloudflare server scaffolds request-render canonical content collection routes and include the appropriate `wrangler.jsonc` and a `deploy` script.

<Aside type="tip">
  After scaffolding, run `nimbus-docs add <slug>` to install components from the registry. See [Adding components](/adding-components) for the workflow.
</Aside>
