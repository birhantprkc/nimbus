Unify the sidebar row across the docs and API rails. The group header is extracted into a shared `SidebarGroupHeader` atom and `SidebarLink` gains an optional `leading` slot, so the API rail (`ApiSidebar`/`ApiSidebarItem`) now composes the same atoms as the docs sidebar instead of re-implementing them. The method chip becomes its own self-scoped `ApiMethodChip` component and rides the `leading` slot. Docs-only sites are unaffected — the only base change is one optional, unused slot. The `api-sidebar` registry item now depends on `sidebar`.

Also aligns the group disclosure caret across both `SidebarGroupHeader` shapes: the linkable (index-page) header previously placed its caret ~6px closer to the edge than the disclosure-only header, so any rail mixing the two — or comparing the docs and API rails — showed carets in different columns. The caret now sits in a single column matching the leaf content edge.

The API reference body now renders its breadcrumb trail through the base `Breadcrumbs` component instead of a forked inline `<nav>`, so the docs and API rails share one breadcrumb look (separator, truncation, middle-collapse). `Breadcrumbs` gains an `endsAtCurrentPage` option (default `true`); the API rail passes `false` because its trail is ancestors-only (every crumb stays a link, and a single-crumb trail still renders). The `api-layout` registry item now depends on `breadcrumbs`.

Two more forked API atoms now compose base components. The deprecated-operation notice renders through the base `Banner` (caution variant, sanitized content string) instead of a bespoke `bg-warning-muted` div — the same shape as the docs version-deprecation banner. The operation route pill renders through the base `Badge` (a shared `methodVariant` map: get→info, post→success, put·patch→warning, delete→danger) with mono/tight-radius overrides and a leading arrow glyph, retiring the hand-rolled `.nb-route` CSS and the duplicated method→colour map. The `api-layout` registry item now also depends on `banner` (`badge` was already a dependency).

Also fixes the code rail's gutter line spacing. `ApiCodeRail` set `.line { display: block }` to hang its line-number gutter, but Shiki already separates lines with literal newline text nodes that a `<pre>` renders as breaks — so every sample line got two breaks (block box + newline) and the request/response code rendered double-spaced. The `.line` rule is dropped; the preserved newlines do the line-breaking and the `::before` gutter counter still increments once per line.

Also fixes three drifts in the API reference shell. `ApiFieldList` gains the `truncated` prop it was missing: when the engine caps a field group at the inline ceiling, the list now renders the "… N more field(s) omitted" note (in parity with the markdown twin, which already emitted it) instead of silently dropping the count; `ApiLayout` forwards `truncated`/`bodyTruncated` at every field-list call site. The reference shell now uses the same header height as the docs layout: its sticky sidebar and code rail sit at `top-14` / `h-[calc(100vh-3.5rem)]` (down from `top-16` / `4rem`), and the `api-reference` feature recipe's example shell + its documented offset contract move from `4rem`/`top-16` to `3.5rem`/`top-14` in step, so a recipe-following site gets one header height across docs and API instead of an 8px mismatch. And the code rail sizes from a dedicated `--nb-code-rail-width` (self-contained `34rem` fallback) instead of borrowing the docs `--nb-toc-width` — a code rail wants far more room than a table of contents, and its width no longer changes when a site retunes its TOC.

Also hardens the docs layout's mobile navigation drawer (shared by the API rail). The hamburger controller now reclaims a drawer caught mid-slide-out — tapping the trigger during the close animation previously cancelled the close timer but left the modal `<dialog>` open with body scroll locked and the panel off-screen, an invisible scroll-locking overlay. It also wires the trigger's `aria-expanded`/`aria-controls`/`aria-haspopup`, closes instantly under `prefers-reduced-motion` instead of waiting out the slide, and dismisses an open drawer when the viewport reaches the desktop breakpoint so focus can't strand on a now-hidden trigger. The open animation now starts on the next frame via a synchronous reflow instead of a double `requestAnimationFrame`, removing a visible two-frame delay before the slide begins.
